# Firebase rules analysis (working security note)

## Scope

- Runtime: Next.js 16 / React 19 / TypeScript.
- Authentication: Firebase email/password and Google popup.
- Authorization: verified Firebase users whose email is one of the two configured administrator emails.
- Realtime Database paths: `/cases/{caseId}` and `/adminPresence/{uid}`.
- Firestore paths: `/contacts/{contactId}` and append-only `/auditLogs/{logId}`.
- No database path is publicly readable.

## Queries and writes

- RTDB: live `onValue` read of `/cases`; client-side weighted search; `push`, `set`, `update`, and `remove` by administrators.
- Firestore: live `onSnapshot(query(collection("contacts"), orderBy("sortOrder")))`; administrator-only batch seed. The current UI has no contact update or delete action.
- Firestore audit logs are create-only in the current UI and immutable by rules; authenticated administrators may read them for a future audit view.
- The server AI endpoint reads `/cases` through the Realtime Database REST API with the same Firebase ID token, so database rules still apply.

## Devil's-advocate review

- Anonymous/public list: denied at root and every data path.
- Signed-in non-admin: denied by verified email allowlist.
- Unverified email/password admin address: denied until verification.
- Unknown fields/schema pollution: denied by Firestore `hasOnly` and RTDB `$other` validator.
- Oversized strings/type juggling: bounded and type-checked on create and update.
- Admin-role self-escalation: no writable roles collection exists; access comes from token email plus server environment verification.
- Created-at/creator mutation: Firestore immutable; RTDB creator must always equal the current admin UID.
- Audit rewriting/deletion: denied.
- Tavily and Gemini keys remain server-only; the AI route verifies the Firebase ID token and the admin email allowlist before reading cases or calling either service.
- The contact list query has no filters or limit. This is safe for the small curated directory but should gain pagination if it grows substantially.
- Validation on 2026-08-18: Firebase CLI 15.27.0 loaded both rulesets successfully in the local Firestore Standard and Realtime Database emulators; RTDB accepted the compiled rules with HTTP 200.
- Remaining limitation: remote project dry-run/deployment depends on Firebase management API connectivity. IAM permission checks passed for the signed-in owner, but `firebase.googleapis.com` timed out from this machine before deployment.
